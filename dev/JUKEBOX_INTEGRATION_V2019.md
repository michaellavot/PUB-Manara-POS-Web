# V2.0.19: native Jukebox management in PUB Manara POS

The new page uses the POS shell, existing CSS/wood assets and owner authentication. No iframe or external browser. Jukebox backend remains separate (current Jukebox project). No live POS charge or song-code issuance API is exposed. The bridge checks the POS access token and live owner grant on each request and maps one verified POS owner terminal to an existing active Jukebox owner. Owner mappings are stored privately in the Jukebox database and must be reprovisioned for a future owner transfer. Deploy `supabase/functions/jukebox-pos-owner/index.ts` to Jukebox Supabase only (verify_jwt=false because it verifies the original POS project's JWT itself); apply `dev/jukebox_pos_owner_v2019.sql` there. Source and migration are part of this POS release; Jukebox data is not part of the POS database snapshot. The bridge only permits approved management actions. No issue/refund/charge/approval operation. Queue mutations are test-only. No new Supabase project.
